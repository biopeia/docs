## UC-0001

`UC-0001` is a user constraint recorded in the same decisions register. It is
not an architecture decision and has no record number, but `AD-0002` and
`AD-0011` rely on it, so its row is reproduced verbatim.

- **Type:** USER CONSTRAINT
- **State:** ACTIVE / ACCEPTED FOR AUDIT SCOPE

The target architecture has NO BACKWARD COMPATIBILITY OBLIGATION: it need not preserve legacy public APIs, obsolete import paths/package names, deprecated schemas/runtime paths, compatibility adapters/shims, old repository topology, or legacy behavior solely for existing consumers. `DEPRECATE` is at most a temporary migration-wave state, not a target disposition. A `COMPATIBILITY_SHIM` may only be proposed for an atomic temporary migration, must name its removal wave, and is excluded from the target architecture. Cross-version compatibility is required only within an explicitly supported target stack/version combination; no indefinite support for earlier generations is implied. Preserve scientific meaning, not legacy implementation: historical artifacts may require their artifact, provenance, old reader/environment/version and interpretation retained as a governed record, without requiring the target runtime to load old schemas indefinitely. This constraint does not declare any current item legacy/junk or authorize unsupported deletion.

Apply to compatibility and migration registers. For each specific item, establish current responsibility and evidence before KEEP/MOVE/SPLIT/MERGE/REWRITE/DELETE/RENAME/ARCHIVE disposition. Retain OP-0002 for scientific-asset inventory and Gate C completeness.
