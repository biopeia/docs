# Biopeia Repository Settings and GitHub Actions Inventory — 2026-10-13

## Objective and linked issue

This read-only baseline fulfills [Docs #152](https://github.com/biopeia/docs/issues/152), derived from implementation tracker [Docs #151](https://github.com/biopeia/docs/issues/151), and supports the accepted [Repository Settings and GitHub Actions Workflow Normalization v1](../design/governance/repository-settings-and-actions-workflow-normalization-v1.md). It records observed GitHub configuration and workflow sources before any rollout. It neither changes configuration nor asserts that current settings conform to the design.

Audit window: 2026-10-13 01:27–01:38 Europe/Madrid (2026-10-12 23:27–23:38 UTC). Repository and workflow data were read from each default branch at the exact revisions below; settings and rulesets were queried through GitHub APIs during the same audit window. Dynamic settings may change independently of those source revisions.

## Changes and exclusions

Included are all eleven in-scope repositories, tracked Actions workflow files, current default-branch SHAs, repository-level Actions and merge settings, visible branch rulesets, available required-check contexts, Dependabot and secret-scanning settings, and evidence limits. Exact workflow source blobs are addressable through each repository's commit permalink. This inventory is diagnostic only: no settings, workflows, branch rules, secrets, or Dependabot configuration were changed.

Excluded are secret values, organization-level secret visibility, untracked GitHub-generated dependency-graph workflows, historical run-by-run outcome audits, and any assessment of scientific/domain correctness. No secret values were queried. Workflow permission and trigger summaries below describe the tracked source; private settings that returned authorization/plan errors remain unknown rather than absent.

## Work class, risks and authority

Read-only cross-domain governance inventory; no implementation authority is exercised. GitHub configuration is mutable, so this is a dated baseline, not a permanent guarantee. Before each implementation PR, re-read the affected repository's current settings, required checks, branch rules and workflow source. Do not use this inventory alone to authorize a change or claim that a private repository is protected.

## Scientific limitations and review findings

This is a configuration and source inventory, not evidence of scientific validity, domain behavior, or passing CI. It does not certify latest workflow runs or establish that a required context is actually emitted by the intended workflow on every merge path. No secret contents were retrieved. Do not interpret a missing API response, HTTP 403/404, empty run sample, or absent visible ruleset as proof of nonexistence where permissions/plan limitations apply.

Observed implementation concerns to track (not fixed by this inventory):

1. `observation` publicly calls `.github-private` reusable workflows for issue triage and project intake; validate access semantics and migrate to an allowed public/private boundary before depending on it.
2. Public reusable-workflow auto-PR checks use older SHA `1f0acc671afe4039c248ed8c466e42fbf790e09a` while the inspected `.github` HEAD is `671b13855d48ea9ec5a81044f05b416ea2cbfd24`.
3. Most repositories use mutable major tags for third-party action references and the org does not require SHA pins.
4. Workflow-level permissions are missing from several CI/publication workflows; GitHub repo default is read-only, but explicit least privilege should be assessed per job.
5. No tracked Dependabot version-update config exists, security-update PRs are disabled, and the exact ecosystems to configure must be derived from manifests/lockfiles per repo.
6. `delete_branch_on_merge` is off in five repositories: `modality`, `docs`, `.github`, `.github-private`, and `biopeia/workspace`.
7. Private branch rulesets and scanning details require an account plan/permission path that exposes them; do not assert parity with public repositories until verified.
